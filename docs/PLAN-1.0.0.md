## 2. 逐条方案

### 2.1 启动检查更新

**现状**（已确认）

- 主进程 `main.js:439` 启动 6 秒后调 `silentCheckUpdate()`；只在 `r.updateAvailable` 时给渲染进程发 `update:available`，失败静默（`main.js:226`）
- 渲染层 `renderer/js/main.js:523` 收到后**只做两件事**：状态栏版本号变 `v1.0.0-dev → vX 可更新` + 一条 toast，**不弹窗**
- 弹窗只在用户主动点「检查更新」/ 点版本号时才走 `promptUpdate()`
- 「已是最新则静默」**已经满足**：`checkUpdates({silent:true})` 分支不弹任何提示

**差距**：只差「发现有新版 → 弹窗」这一步。

**方案（已定：每次启动都弹，可勾选忽略）**

1. `update:available` 回调改为 `await promptUpdate(r.latest)`，复用已有的 `updateAvailableDialog`（版本号、大小、时间、更新说明、下载按钮都在）
2. 弹窗内加一个 **「不再提醒此版本」勾选框**：
   - **未勾选** → 每次启动都弹（符合「每次启动都弹」）
   - **勾选后** → 写入 `userData/update-muted.json`（记 `{ version }`），此后启动不再弹窗，只保留状态栏 `v1.0.0-dev → vX 可更新` 标记和一条轻 toast
   - 换了新版本号 → 记录不匹配，**重新开始弹**
3. **点右下角版本号 → 无论是否忽略，都重新弹出完整弹窗**（当前 `statVersion` 已绑 `checkUpdates()`，需让它绕过忽略状态强制弹）
4. **避让首次配置流程**：`state.configured === false` 时不弹，配置保存后补一次检查
5. 主进程探测时机不动（6 秒），避免和窗口首次渲染抢资源

**改动文件**：`renderer/js/main.js`（onAvailable 回调、statVersion 点击、忽略状态判断）、`renderer/js/util.js`（`updateAvailableDialog` 加勾选框，返回 `{ choice, mute }`）、`electron/main.js` + `preload.js`（读写 `update-muted.json`）

**验收**：装旧版启动 → 6 秒后自动弹更新框；不勾忽略 → 下次启动仍弹；勾了忽略 → 下次只留状态栏标记；点版本号 → 忽略状态下也能重新弹出；无新版时全程无感知；未配置连接时不弹。

**进度**：✅ 已完成。`electron/update.js` 新增 `MuteStore`（`userData/update-muted.json`，只记版本号）；`updateAvailableDialog` 改为返回 `{ action, mute }` 并加「不再提醒此版本 vX」勾选框；渲染层 `handleAvailableUpdate()` 负责三处让行（未配置连接 → 暂存 `state.pendingUpdate`，配置完成后 `flushPendingUpdate()` 补弹；已忽略该版本 → 只留状态栏标记 + toast；已有弹窗在处理 → 直接跳过）。手动点版本号走同一条 `promptUpdate()`，不受忽略影响。

### 2.2 左侧目录树

**现状**

- 完全没有侧栏。`body` 是 `flex-direction: column`，`#fileArea` 直接占满剩余高度
- 目录信息只能靠面包屑和 `.`/`..` 行，跨层级跳转要先返回再进入
- `s3.list` 一次返回 `dirs + files` 全量

**方案**

1. **布局**：`index.html` 顶部新增 `<div id="mainRow">`，内含 `<aside id="treePanel">` + 现有 `<main id="fileArea">`，`display:flex`
2. **懒加载树**：只在展开节点时拉该层子目录。新增轻量 IPC `s3:listDirs(prefix)`，复用 `listDir` 但 `Delimiter:'/'` + 只取 `CommonPrefixes`、`MaxKeys` 限制，**不要把文件也拉回来**
3. **联动**
   - 树节点单击 / 双击 → `loadDir(key)`
   - 主区域切换目录 → 树自动展开**祖先链**并高亮当前节点。祖先链直接从 `currentDir` 按 `/` 拆段即可构造，无需请求
   - 上传 / 新建 / 删除后，失效对应节点的子目录缓存并刷新已展开部分
4. **状态持久化**：面板宽度（拖拽分隔条 + 记忆）、折叠状态、上次展开的节点集合，存 `userData/ui-state.json`
5. **右键菜单**：刷新、在此新建文件夹、复制路径、在文件区定位

**建议**：树默认展开到根 + 记住上次展开项；节点不显示文件，只显示目录（避免和主区域重复）。

**改动文件**：`renderer/index.html`、`renderer/css/app.css`、新增 `renderer/js/tree.js`、`renderer/js/main.js`（联动）、`electron/s3.js` + `electron/main.js` + `electron/preload.js`（listDirs）

**验收**：进入深层目录后树自动定位；1000+ 子目录的层级展开不卡顿；折叠后重启保持；拖拽分隔条流畅。

**进度**：✅ 已完成（`94eb066`）。落地为 `renderer/js/tree.js`（渲染 + 展开状态 + 拖宽折叠）、`s3:listDirs`（只取 CommonPrefixes）、`ui-state.json`（宽度/折叠/展开节点）。单向数据流已落实：`onOpen` 只由树点击触发，`setCurrent` 不回调。

### 2.3 文件类型图标

**现状**

- `renderer/js/main.js:118` 硬编码三元：`r.isDir ? '📁' : '📄'`，所有文件同一个 emoji
- CSS `.file-ic` 容器 26×26、圆角 6px，已有 `.dir` / `.file` 两种底色，扩展位现成

**方案**

1. **载体选内联 SVG，不用 emoji**：emoji 在 Windows / macOS 渲染差异大（Segoe UI Emoji vs Apple Color Emoji），大小和颜色不可控，也没法按类别着色
2. 新增 `renderer/js/fileicon.js`：扩展名 → `{ category, color }` 映射表，配一份 `<symbol>` 图标集（放 `index.html` 隐藏 `<svg>` 里，用 `<use href="#ico-xxx">` 引用）。**不需要改 CSP**，同文档内联 SVG 不受 `img-src` 限制
3. 类别（先定这些，可按需加）：文件夹、图片、视频、音频、文档、表格、演示、PDF、压缩包、代码、文本、安装包、字体、其他
4. **兜底顺序**：扩展名 → 文件名特征（`Dockerfile`、`Makefile`、`.gitignore` 等无扩展名文件）→ 默认文件图标
5. `.file-ic` 增加按类别着色（每个类别一个柔和底色 + 前景色，沿用 `--accent` 那套透明度写法）
6. 目录保持现有蓝色系，但要和文件明显区分（可加轻微立体感或统一描边）

**改动文件**：`renderer/js/fileicon.js`（新）、`renderer/index.html`（symbol 集）、`renderer/css/app.css`、`renderer/js/main.js`（行渲染处改为 `fileIconHtml(name, isDir)`）

**验收**：`.png/.jpg` 显示图片图标、`.zip` 压缩包图标、`.docx` 文档图标；无扩展名文件不报错；深浅色下都清晰；纯字符串拼接、无 DOM 依赖，分页渲染时直接复用。

**进度**：✅ 已完成。`renderer/js/fileicon.js` 提供 `categoryOf()` / `fileIconHtml()`，13 个类别 + `dir`；图标是 `index.html` `#iconDefs` 里的 `<symbol>`，行内只用 `<use href="#ico-xxx">`，颜色由 `.file-ic.<category>` 的 currentColor 控制。目录树图标一并换掉，不再有 emoji。

### 2.4 大目录量优化

**现状问题**（逐条对应代码）

| 问题 | 位置 | 后果 |
| --- | --- | --- |
| `listDir` 无上限，`ContinuationToken` 一路翻到底 | `electron/s3.js:75-102` | 10 万对象要发 100 次请求，加载几十秒，内存吃满 |
| `renderTable` 一次性 `innerHTML` 拼全量行 | `renderer/js/main.js:85-129` | 上万行 DOM 直接卡死；每次选择变化都全量重绘 |
| 选择 / 勾选操作触发整表重绘 | `selectOnly` / `toggleSelect` / `rangeSelect` | 大目录下点一下卡一下 |
| 每次上传完成 / 删除后重新拉整个目录 | `loadDir(currentDir, {silent:true})` 多处 | 重复请求，列表跳动 |
| 无排序、无过滤、无搜索 | — | 找文件只能肉眼扫 |
| 无加载进度反馈 | `loadingMask` 只有 spinner | 大目录时用户不知道在等什么 |

**方案（已定：游标分页 + 服务端前缀搜索，对齐青云控制台网页版）**

先明确 S3 协议的三条硬限制，方案是在这个前提下设计的：

| 限制 | 说明 | 后果 |
| --- | --- | --- |
| 只有游标、没有偏移量 | `ListObjectsV2` 用 `ContinuationToken`，不是 `offset/page` | 只能「上一页 / 下一页」顺序翻，**不能跳到第 N 页** |
| 无总条数 | `KeyCount` 只是本页条数 | 显示「共 N 项」必须遍历全部对象，代价等同全量列举 |
| 只有前缀匹配 | 服务端只认 `Prefix`，没有中缀/模糊 | 搜索等价于 `LIKE '关键词%'`，搜不到「名字中间包含」的对象 |

实施：

1. **游标分页，页大小 200**
   - 主进程按 `(dir, 搜索词)` 维护会话：`tokens[]`（第 n 页的起始 token）+ `pages`（已拉取页缓存）
   - IPC `s3:listPage({ dir, pageSize, cursor, keyword })` → `{ entries, isTruncated, nextToken, page }`
   - **上一页**：命中页缓存直接返回；未命中用 `tokens[page-1]` 重拉（token 只能前进式获取，后退必须重拉或读缓存）
   - 分页条：`上一页 / 下一页` + 已访问页码（可点）+「还有更多」标记。**不做首页/末页跳转**（末页不可知）
2. **搜索切模式**：搜索框有内容时进入搜索模式，`Prefix = base + dir + 关键词`，结果同样分页；清空回到浏览模式。默认只搜当前层，勾「包含子目录」则去掉 `Delimiter` 递归搜（结果里带相对路径）
3. **渲染层**
   - 单页 200 行，**不需要虚拟滚动**（原计划作废，复杂度大幅下降）
   - 选择态增量更新：只 `classList.toggle` 目标行，不再 `renderTable()` 整表重绘
   - 加载中显示「正在加载第 N 页…」，不再是干等 spinner
4. **目录往返缓存**：会话内记住最近访问目录的当前页，从子目录返回时秒回；点「刷新」主动失效

**本地缓存评估**（按你的要求）

单条 `{name, key, size, mtime}` 在 V8 里约 **350–500 B**（对象头 + 两个字符串 + ISO 时间串 + Map 槽位）。

| 规模 | 估算内存 | 结论 |
| --- | --- | --- |
| 200 条（1 页） | ~0.1 MB | 无感 |
| 4,000 条（20 页） | ~2 MB | **可接受，定为默认上限** |
| 10,000 条 | ~4–5 MB | 可接受，但相对收益已明显下降 |
| 100,000 条 | ~40–50 MB | 不建议常驻，GC 压力可见 |
| 1,000,000 条（整桶） | ~400–500 MB | 不可接受 |

结论：**缓存只做「最近访问的页」，LRU 上限 20 页（约 2MB），不缓存整目录、不缓存整桶。** 前缀搜索走服务端，零内存成本且能命中未加载的页 —— 这是默认搜索方式。

如果将来确实需要中缀模糊（搜「名字中间包含」），只能本地全量，届时做成**显式动作**「在当前目录中深度搜索」：用户主动点、显示已拉取进度、5 万条上限并提示内存占用，结果用完即释放，绝不常驻。

**分页方案的固有代价（需要接受）**

- **无法全局排序**：点列头排序只作用于当前页，跨页顺序由 key 字典序决定
- 无总条数、无页码跳转、无末页
- 翻页过程中对象增删会导致结果漂移（S3 不提供快照一致性）

**改动文件**：`electron/s3.js`（`listPage` / `searchPage`，`listAll` 保留给删除用）、`electron/main.js` + `preload.js`（IPC 透传）、`renderer/js/main.js`（分页状态 + 渲染重构，改动最大）、`renderer/index.html`（分页条 + 搜索框）、`renderer/css/app.css`

**验收**：10 万对象的目录首屏 1 秒内出第一页；翻页 < 800ms；单页 200 行选中 / 全选 / Shift 连选无卡顿；前缀搜索能搜到尚未加载页的对象；上一页秒回；内存长期稳定在分页缓存上限内。

**进度**：✅ 已完成。落地要点：

- `s3.listDir` 改为**单次请求一页**（`MaxKeys` 200 + `ContinuationToken`），返回 `{ dirs, files, truncated, nextToken }`；`listAll` 保持不变，仍给删除用
- 渲染层 `state.page = { index, tokens[], nextToken, hasMore }` + `pageCache`（LRU 20 页），上一页命中缓存秒回
- 搜索为**主动触发**：回车 / 点搜索按钮才发请求（输入框内容与已生效关键词不一致时按钮染成强调色），Esc 或 ✕ 清空即回当前目录完整清单；搜索期间不盖遮罩（只在搜索框图标上转圈）
- 搜索走 `s3.searchDir`：单次请求 `Prefix = dir + 关键词`，**保持 S3 原生的字节精确（大小写敏感）语义**。曾试过并发「原样/全小写/全大写/首字母大写」四变体绕过，但接口不支持就不在客户端造兼容——结果不可预期且请求量翻倍，已回退
- 搜索结果不分页（游标只能一路往后翻，搜索该做的是加长前缀收窄），分页条收起并显示「匹配 N 项」；清空即回浏览模式
- 选择 / 全选 / Shift 连选改为 `repaintKeys()` 只切目标行的 class 与勾选框，冒烟里以「同一行 DOM 节点是否被复用」作为断言
- 列头排序只作用于当前页（D5），目录恒在前，列头带 ▲/▼ 与「仅当前页」提示
- 顺带修掉一个既有缺陷：`s3.listDir` 返回的目录项字段是 `dir: true`，渲染层却读 `isDir`，导致**目录显示成文件、双击进不去**。现在在 `loadPage` 统一成 `isDir`

**改动文件**：`renderer/index.html`（移 `<nav id="breadcrumb">`）、`renderer/css/app.css`（面包屑行样式）、`renderer/js/main.js`（删 `visibleRows` 与全部 `special` 分支、空白右键加返回上级）

## 3. 实施顺序

```
⑤ 面包屑归位 + 删占位行 ┐
② 目录树（布局定型）     ┘ 同一批：都在改 body / #fileArea 的布局结构
      ↓
③ 文件图标（行内容定型）
      ↓
④ 大目录优化（游标分页重构，把 ②③⑤ 的产物包进去）
      ↓
① 启动更新弹窗（独立，最后收尾，不打断调试）
```

理由：② 先改外层布局，④ 只动 `#fileArea` 内部，先做 ② 可以避免 ④ 做完再改布局返工；③ 和 ④ 都改行渲染，③ 先定图标接口，④ 重构时直接调用；① 完全不依赖 UI 结构，放最后随时可插队。

**⑤ 与 ② 必须同批**：两者都在改 `body` → `#mainRow` → `#fileArea` 这条布局链，分开做等于把同一片区域拆两次。合并后一次收敛为最终形态：

```
顶栏     Q  QingStorClient / bucket                    [设置]
├──────────────┬─────────────────────────────────────────────┐
│ 目录树        │ 工具栏  ↑上级 │ 上传 下载 新建 删除 │ 刷新    │
│ (可拖宽/可折叠)│ 面包屑  ☁ bucket / 资料 / 2026              │
│              │ 表头    名称  大小  修改时间                 │
│              │ 列表    …（真实条目，无 . / ..）             │
└──────────────┴─────────────────────────────────────────────┘
```

注：④ 从「虚拟滚动」改为「游标分页」后，渲染层复杂度明显下降（单页 200 行直接渲染即可），但仍要重写 `renderTable`、选择态与刷新链路，所以仍排在最重的档位。
